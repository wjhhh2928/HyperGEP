# HyperGEP 修正版中文使用手册

适用版本为 `corrected-v1`，训练代码基于本地提交 `187fb60`。首次使用时，在 Windows PowerShell 中执行第 1 节的一折 demo。准备好论文数据后，按第 3 节校验输入，再选择第 4 节的实验入口。除特别标注为 Bash 的命令外，示例均在仓库根目录下执行。

| 运行场景 | 输入 | 结果用途 |
| --- | --- | --- |
| 合成 demo | 程序生成的 `demo` 数据 | 验证安装、训练、推理、指标和绘图 |
| G2F 真实短测 | 本机已整理的少量 G2F 原始记录 | 验证列对齐、真实数据留出流程与 checkpoint 回放 |
| 论文候选实验 | 已核实来源、版本、标签、样本和 SNP 顺序的完整数据 | 按冻结协议开展正式重训及科学比较 |

## 1. 安装和运行第一个 demo

在资源管理器中打开修正版项目文件夹，在地址栏输入 powershell 并回车。用以下命令确认当前目录包含 README.md 和 experiments 文件夹。

```powershell
Get-Location
Get-Item -LiteralPath README.md,experiments
python --version
```

发布环境方案使用 Python 3.11。请先确认上一步选中你打算使用的 Python。有可用的项目环境时可直接使用该环境。从零搭建 CPU 虚拟环境时执行以下命令。通过虚拟环境的 Python 路径运行即可。

```powershell
python -m venv .venv
$HgPython = (Resolve-Path '.venv\Scripts\python.exe').Path
& $HgPython -m pip install --index-url https://download.pytorch.org/whl/cpu torch==2.5.1
& $HgPython -m pip install -r requirements.txt pytest
& $HgPython -c "import torch; print(torch.__version__); print('CUDA:', torch.cuda.is_available())"
```

下文用 `python` 表示当前项目解释器。如果沿用上述虚拟环境，PowerShell 示例中的 `python` 可以替换为 `& $HgPython`。需要 XGBoost、LightGBM 或 TabNet 时，再执行 `python -m pip install -r environment/comparators.txt`。使用 GPU 时请选择与本机驱动兼容的 CUDA 版 PyTorch，并以 `torch.cuda.is_available()` 的输出和实际单折测试确认可用性。

```powershell
python -m experiments.run_main --dataset demo --fold 0 --device cpu --output-dir artifacts/demo/manual_main
python -m scripts.aggregate_results artifacts/demo/manual_main --demo --output-dir artifacts/demo/manual_main/summary
python -m pytest -q
```

终端出现 `SYNTHETIC DEMO` 和 `COMPLETED Full_Model seed 42 fold 0` 即表示 demo 训练完成。进入 `artifacts/demo/manual_main/summary/` 查看 `fold_metrics.csv`、`heldout_predictions.csv` 和诊断图。小预算 demo 的指标仅用于检查流程。上次交付已有 9 项 CPU 测试通过，实际使用的本机环境见 [测试报告](../reports/TEST_REPORT.md)。

## 2. 使用本机 G2F 摘录做真实数据短测

如果本机已有 `artifacts/real_smoke/assets/smoke.yaml` 和配套的 `assets/g2f/`，可以直接运行。该摘录包含 160 条记录、10 个环境和 64 个 SNP，短测结果写入独立目录。

```powershell
Test-Path -LiteralPath 'artifacts/real_smoke/assets/smoke.yaml'
python -m experiments.run_main --dataset g2f --config artifacts/real_smoke/assets/smoke.yaml --data-dir artifacts/real_smoke/assets --fold 0 --device cpu --output-dir artifacts/real_smoke/manual_record
python -m experiments.run_loeo --dataset g2f --config artifacts/real_smoke/assets/smoke.yaml --data-dir artifacts/real_smoke/assets --min-test-samples 16 --fold 0 --device cpu --output-dir artifacts/real_smoke/manual_loeo
```

第二条实验命令会将一个完整环境及其记录作为外层测试集。用第 6 节的方法查看 `loeo_environment.csv` 或回放权重。如果本机缺少摘录，可用 `python -m scripts.stage_g2f_smoke --help` 查看从本地 G2F 原始表生成摘录的参数。该脚本要求输出目标中的 `g2f/` 尚不存在。摘录会标记为 `real_smoke`，正式汇总脚本会自动跳过。

## 3. 准备和校验论文候选数据

### 四个必需文件

`--data-dir` 指向两个数据集目录的上一级。默认目录结构如下。

```text
data/
├─ maizegep/
│  ├─ phenotypes.csv
│  ├─ genotypes.csv
│  ├─ environments.csv
│  └─ provenance.json
└─ g2f/
   ├─ phenotypes.csv
   ├─ genotypes.csv
   ├─ environments.csv
   └─ provenance.json
```

| 文件 | 一行代表什么 | 关键列和校验规则 |
| --- | --- | --- |
| `phenotypes.csv` | 一条表型观测 | `sample_id` 唯一，含 `genotype_id`、`environment_id` 和配置中的性状列。重复试验观测各用自己的样本 ID。地点留出时还需 `site_id`，同一环境只能对应一个地点。 |
| `genotypes.csv` | 一个基因型 | `genotype_id` 唯一，其他列为数值 SNP 剂量。保留训练使用的标记名称和列顺序。 |
| `environments.csv` | 一个环境 | `environment_id` 唯一，其他列为预测时可用的数值特征。LOEO 地理图需要数值列 `latitude` 和 `longitude`，这两列也会进入环境输入。 |
| `provenance.json` | 一版数据的来源 | 记录 `dataset_version`、`origin`、`license`、`label_provenance`、`environment_availability`、`preprocessing`、`row_alignment_verified` 和三份表的 `sha256`。 |

表型中的每个基因型和环境 ID 都必须能在对应特征表中匹配。保留 ID 前导零，清除键的首尾空格。输入采用原始观测尺度，缺失值留空。配置允许用 TSV 替代 CSV，但文件名和扩展名要与 `datasets.<数据名>.data_paths` 一致，文件应位于指定数据根目录下。

默认性状为 MaizeGEP 的 `DTT`、`DTS`、`DTM`、`PH`、`EH`、`100KW`、`EL`、`Y`、`KNPR`、`ED`、`RNPE`，以及 G2F 的 `Y`、`PH`、`GM`。表头须与配置完全一致。保存数据前核实数据来源与加工记录。只有确认已完成 ID 对齐且数据以原始尺度提供时，才将 `row_alignment_verified` 设为 `true`、将 `preprocessing` 设为 `raw`。

### 写入散列和检查数据

表格定稿后计算 SHA256。把三条散列分别放入 `sha256.phenotypes`、`sha256.genotypes` 和 `sha256.environments`，其余来源字段按核实的信息填写。用 UTF-8 保存文件。

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'data/maizegep/phenotypes.csv','data/maizegep/genotypes.csv','data/maizegep/environments.csv' | Select-Object Path,@{Name='SHA256';Expression={$_.Hash.ToLowerInvariant()}}
python -m experiments.run_main --dataset maizegep --data-dir data --dry-run
python -m experiments.run_main --dataset g2f --data-dir data --dry-run
```

`--dry-run` 会读取并核验输入并输出 JSON 任务计划。看到 `PENDING` 表示该任务可以安排，看到 `BLOCKED` 则检查同一条目的 `reason`。干跑能输出阻塞计划并返回退出码 0，自动化脚本须同时判断计划内容。

若运行基因组区域归因，另准备 `data/<数据名>/markers.csv`，包含 `marker_id`、`chromosome`、`position` 和 `reference_build`。每个 SNP 列名都要有唯一坐标，`position` 使用从 1 开始的基因组坐标，且使用同一参考组装。数据获取入口和字段细节见 [数据说明](DATA.md)。

## 4. 启动各实验

下表给出 8 个入口。表中的模块名可接在 `python -m` 后面。实验命令均从当前配置重新训练或复用由同一运行身份校验通过的结果。

| 实验 | 模块 | 选项和产物 |
| --- | --- | --- |
| HyperGEP 主实验 | `experiments.run_main` | `Full_Model`，输出外层预测、指标和内层 OOF 记录 |
| 机器学习基线 | `experiments.run_baselines` | `GBLUP_Proxy`、`AdaBoost`、`RandomForest`、`XGBoost`、`LightGBM`、`MLP`、`TabNet` |
| 基因组 CNN 对照 | `experiments.run_genomic_comparators` | `DNNGP_reconstructed`、`DeepGS_reconstructed`，基于公开拓扑的重建版 |
| 消融 | `experiments.run_ablation` | `Full_Model`、`wo_HGAT`、`wo_CNN`、`wo_CrossAttention`、`wo_MetaFusion`、`legacy_fusion` |
| 负迁移 | `experiments.run_negative_transfer` | `STL`、`MTL`、`Full_Model`。用同一协议跑齐三种模型后汇总配对差异。 |
| 邻居数敏感性 | `experiments.run_sensitivity` | 论文候选配置含 `k3`、`k5`、`k7`、`k9`、`k11` |
| 留一环境 | `experiments.run_loeo` | `--min-test-samples` 控制环境的最少测试记录数，论文候选配置默认 80 |
| SNP 解释性 | `experiments.run_interpretability` | `--analysis gradient` 生成梯度，`--analysis all` 还为适用性状执行留出遮蔽 |

### 单折命令

以下示例使用正式目录 `data/`，输出默认写入 `artifacts/corrected/`。首次使用相同配置运行某个模块时可加 `--dry-run`。同一比较中的不同变体和基线使用同一数据版本、划分与 seed。

```powershell
python -m experiments.run_main --dataset maizegep --fold 0 --device cpu
python -m experiments.run_baselines --dataset maizegep --variant RandomForest --fold 0 --device cpu
python -m experiments.run_genomic_comparators --dataset g2f --variant DeepGS_reconstructed --fold 0 --device cpu
python -m experiments.run_ablation --dataset maizegep --variant wo_CrossAttention --fold 0 --device cpu
python -m experiments.run_negative_transfer --dataset g2f --variant all --fold 0 --device cpu
python -m experiments.run_sensitivity --dataset maizegep --variant k9 --fold 0 --device cpu
python -m experiments.run_loeo --dataset maizegep --min-test-samples 80 --fold 0 --device cpu
python -m experiments.run_interpretability --dataset maizegep --analysis all --fold 0 --device cpu
```

`GBLUP_Proxy` 使用按训练折缩放的 SNP 和线性基因组核岭回归。比较旧版单 key 注意力时，`legacy_fusion` 使用修正版数据划分。历史复现实验请使用第 7 节的审计入口。

### 参数、划分与配置

| 参数 | 用法 |
| --- | --- |
| `--dataset` 和 `--config` | 数据集为 `maizegep`、`g2f` 或 `demo`。真实数据默认读 `configs/paper.yaml`，demo 默认读 `configs/demo.yaml`。自定义配置要包含所选数据集。 |
| `--variant` | 指定表中的模型名，区分大小写。省略或用 `all` 会运行该实验的所有变体。 |
| `--fold` 和 `--seed` | 外折从 0 编号。省略 `--fold` 会跑合格的全部外折。省略 `--seed` 使用配置中的列表。LOEO 跳过记录数不足的环境后，合格折号可以不连续，以干跑计划为准。 |
| `--trait` | 如 `--trait Y --trait PH`。主模型和早期耦合 MTL 仍训练配置中的全部性状，导出所选性状的指标和预测。独立基线可按所选性状训练。 |
| `--split` | `record` 随机留出观测，`genotype` 留出基因型，`environment` 留出环境，`site` 留出地点，`genotype_environment` 留出基因型与环境的组合。最后一种可在两侧出现同一基因型或环境，具体组合保持隔离。LOEO 自带划分，使用 `--min-test-samples`。 |
| `--test-strategy` | `refit` 用整个外训练折重拟合性状分支后预测外测试集，`ensemble` 使用冻结的内折分支集成。适用于带 Meta-Fusion 的流程。 |
| `--data-dir` 和 `--output-dir` | 输入数据根目录与结果根目录，也可从 `DATA_DIR` 和 `OUTPUT_DIR` 读取。命令显式传参优先。 |
| `--device` | `cpu`、`cuda` 或 `cuda:0` 等单设备。 |

默认的 `record` 划分允许同一基因型或环境同时出现在训练和测试折。需要测试跨环境泛化时，使用环境分组或 LOEO。分组策略和折数需要足够的独立组。论文候选配置采用外 5 折、内 5 折和 `refit`。单个 seed 的主模型在 MaizeGEP 上需要 330 个性状分支拟合和 5 个 Meta 模型拟合，在 G2F 上需要 90 个性状分支拟合和 5 个 Meta 模型拟合。全量运行前先用最终数据和设置测量一折的耗时与显存。

更改训练预算、分组方式或数据文件名时，复制一份 YAML 作为自定义配置，以 `--config` 指定并保留版本记录。常看的字段包括 `outer_cv`、`inner_cv`、`training_parameters`、`evaluation` 和 `datasets`。

## 5. 批量运行和断点续跑

### 批量入口

以下命令在已选中项目 Python 环境的 Git Bash、WSL 或 Linux Bash 中执行。全量脚本会安排两个数据集的主要比较、MaizeGEP LOEO 和相应汇总。正式数据、可选基线依赖和两套标记坐标准备好后再执行。CPU 示例可按资源改成 `DEVICE=cuda:0`。

```bash
DATA_DIR=data OUTPUT_DIR=artifacts/corrected DEVICE=cpu bash scripts/run_full.sh
```

### 续跑中断任务

使用原来相同的命令和输出目录，加上 `--resume`。下面例子续跑与第 4 节相同的 G2F 负迁移一折。

```powershell
python -m experiments.run_negative_transfer --dataset g2f --variant all --fold 0 --device cpu --resume
```

运行身份包含提交、代码、配置、数据、折成员和运行环境。深度模型可从最近一次保存的 epoch 继续。已完成且文件哈希一致的运行会显示 `COMPLETED (reused)`。更换配置、数据或设备会形成新的运行身份。如果报告完成产物已改变，保留旧结果，给重跑指定新的 `--output-dir`。

## 6. 查找结果、汇总和回放

结果目录按以下层级组织。每个结果根目录还有 `task_plan_*.json`，用于定位未完成的任务。

```text
<输出根>/corrected-v1/<数据集>/<实验>/<变体>/seed_<seed>/fold_<两位折号>/<运行ID>/
```

| 文件 | 看什么 |
| --- | --- |
| `run_manifest.json`、`config_resolved.yaml` | 运行状态、输入和输出散列、所用提交、实际参数和评估协议 |
| `predictions.csv`、`metrics.csv` | 外层留出预测和指标。以 `label_valid` 和 `valid_sample_count` 核对有效标签数。PCC 遇到常量或样本不足时查看 `PCC_reason`。 |
| `split_indices.tsv`、`oof_predictions.csv` | 外折与内折成员，以及带 Meta-Fusion 流程的内折 OOF 预测和监督来源 |
| `training_log.csv`、`data_audit.json` | 训练耗时、阶段信息及基因型、环境、标记与标签数量 |
| `checkpoint.pt`、`checkpoints/`、`preprocessing_state.json` | 深度模型冻结参数及预处理。传统基线的模型文件为 `checkpoint.joblib`。 |
| `graph_statistics.csv`、`meta_attention_mean.csv` | 使用超图的运行统计和 Meta-Fusion 注意力均值，根据变体生成 |
| `loeo_environment.csv`、`heldout_snp_gradients.npz`、`s6_heldout_masking.csv` | LOEO 环境评价、留出 SNP 梯度以及适用性状的遮蔽结果，根据实验生成 |

### 汇总分析

以下命令读取已完成、散列通过的结果。用于同一比较的结果放在同一结果根目录中，并保持每个任务位置只有一份冻结候选结果。只完成一折时，汇总只覆盖该折。负迁移汇总必须从同一外折的 `STL`、`MTL`、`Full_Model` 三方匹配，配对表为 `paired_transfer.csv`。

```powershell
python -m scripts.aggregate_results artifacts/corrected --output-dir artifacts/corrected/summary
python -m scripts.meta_dependencies artifacts/corrected --output-dir artifacts/corrected/trait_dependencies
python -m scripts.plot_loeo artifacts/corrected/corrected-v1/maizegep/loeo --trait Y --output-dir artifacts/corrected/loeo_figures
python -m scripts.attribution_panels artifacts/corrected/corrected-v1/maizegep/interpretability --markers data/maizegep/markers.csv --output-dir artifacts/corrected/maizegep_attribution
```

LOEO 地理图需要同一数据版本和 seed 的正式结果及完整坐标。解释性面板输入也要选同一数据版本、评估协议和 seed。缺少标记坐标时，可先省略 `--markers` 运行支持的非区域面板，并在 `analysis_manifest.json` 核对区域分析状态。注意力权重和梯度归因用于解释模型依赖，科学因果关系需要独立证据。

### 回放本机可信 checkpoint

下面示例从第 2 节的真实 G2F LOEO 短测输出中找到运行目录。也可直接把一条 `run_manifest.json` 所在目录作为参数传入。

```powershell
$HgRun = (Get-ChildItem -LiteralPath 'artifacts/real_smoke/manual_loeo' -Recurse -Filter run_manifest.json | Select-Object -First 1).Directory.FullName
python -m scripts.replay_checkpoint "$HgRun" --data-dir artifacts/real_smoke/assets
```

此入口适用于可信的已完成 HyperGEP 深度运行。它会核验数据标识、折成员和运行文件散列，回放外层预测并与原始 `predictions.csv` 比较。看到 `Checkpoint replay verified` 表示两者在容差内一致。

### Code Ocean 运行方式

在 Capsule 中将仓库源码和 `run` 放到 `/code`，把获准的数据或复现包挂载到 `/data`。环境构建使用 `environment/postInstall`，结果默认写入 `/results`。在本机 Bash 验证 demo 时显式指定本地结果目录。

```bash
REPRO_MODE=demo OUTPUT_DIR=artifacts/demo/manual_capsule bash ./run
```

| `REPRO_MODE` | 执行内容 |
| --- | --- |
| `demo` | 合成数据一折训练、指标和绘图 |
| `reproduce` | 默认模式。读取 `/data/reproduction_bundle/` 中的正式预测包，校验 SHA256 后重算指标和诊断图。清单的 `scope` 为 `paper_candidate`，`files` 记录相对路径与 SHA256。缺包时写出 `BLOCKED`。 |
| `full` | 调度正式全量重训和汇总，需正式数据、相应依赖和计算资源 |

本机 Bash 已验证 demo 和缺包阻塞路径。实际 Capsule 和 Docker 环境的验证状态见 [Code Ocean 就绪度](../reports/CODE_OCEAN_READINESS.md)。导入、复现包和容器配置细节见 [Code Ocean 配置](CODE_OCEAN.md)。

## 8. 常见问题与发布检查

| 现象 | 处理方法 |
| --- | --- |
| 找不到 `experiments` 或 `hypergep` | 确认当前目录是 `HyperGEP-corrected` 并使用项目 Python。 |
| `Data assets missing` 或 `Provenance is missing` | 核对数据根目录、配置中四个文件的路径和来源字段，随后重新干跑。 |
| `Data SHA256 mismatch` | 比对当前文件与批准的输入版本。确认文件变化已获认可后再重算散列，并登记新的数据版本。 |
| `Unmatched phenotype environment/genotype identifiers` | 检查 ID 类型、前导零和三表映射。若环境或基因型缺少特征，回到原始映射修正。 |
| CUDA 不可用 | 先用 `--device cpu` 验证流程，再核对 CUDA 版 PyTorch、驱动和可见显卡。更换设备后运行身份会变化。 |
| 某个环境或折没出结果 | 查 `task_plan_*.json`、运行清单的错误信息，以及 LOEO 的 `loeo_environment_eligibility_*.csv`。同时检查各折可用组和有效标签数。 |
